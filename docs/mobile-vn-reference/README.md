## 已确定的体验目标

- 手机竖屏、固定一屏，不再把图片和小头像夹在长篇正文里。
- 背景作为舞台铺开，透明 PNG 人物立绘叠加其上，下方固定姓名和对白框。
- 一次显示一句或一小段，点按推进；出现选项时等待选择，不上下滚动阅读剧情。
- 图片中的手机圆角外框只是对照展示用。真正手机页面应利用可视区，**不要在手机屏幕里再套一个手机壳**。
- 示意里的选择文案、放大按钮、方案名称不属于游戏剧情，不可复制到剧本中。
- 回看、自动等工具栏按钮也是布局示意；最终只显示已经实现的功能，不留空按钮。

## 使用原图，不使用截图里的缩略画面代替素材

样板直接使用仓库现有素材，没有重新画人物：

- 背景：`assets/bg/北村_徐家书房.jpg`
- 透明立绘：`assets/char/徐恩淑_常态.png`

HTML 内嵌的是便于传递的压缩预览。正式游戏必须引用 `assets/` 下的原始 JPG/PNG，保留透明通道；不能把背景和人物压成一张图，也不能把本目录示意截图当成游戏素材。

ZIP 内 `source-assets/` 提供这两张原图的原样副本，便于只拿到参考包时查看；在仓库实现时仍使用上述 `assets/` 路径。其余游戏素材都在最新 `main` 中，不需要重新生成。

## 实施范围与容易做错的地方

1. 先读根目录 `AGENTS.md`、`README.md`，以及 `tools/build.py`、`tools/story.js`、`tools/story.css`、`tools/ui.tw`。允许为本次界面重构修改生成源，不手改生成的 HTML、manifest 或素材 README。
2. 保留剧情源文、数值变化、分支条件、选择和69个结局。本次不是改写剧情，也不是重做美术。
3. 对白、旁白、背景、CG、立绘、表情、BGM和音效都要按剧情顺序推进。**不能先执行整段脚本和全部媒体，再仅把文字分批显示**；否则人物、背景和声音会串到后文。
4. 点击菜单、存档或选项不能穿透为“继续”。选项等待期间不自动越过。若做打字效果，第一次点击补完当前句，下一次点击才推进。
5. 保存的不仅是章节，还包括当前句/事件位置和必要的演出状态。读取存档、后退、检查点恢复后，人物、背景和音乐须正确；不无故重复播放一次性音效。理解 SugarCube 的 pre-play 历史与活动变量区别，不把游标只存到无法入档的全局变量。
6. 保留 `admin.html` 的章节/具体话选择、四种状态策略、撤销跳转，以及与正式版隔离的存档、结局和检查点。跳章时同时重置对应演出游标，避免进入新章却显示上一章画面。
7. 手机安全区、动态地址栏和横竖屏切换要处理好；桌面居中展示竖屏舞台。普通阅读不整页滚动；选项过多、回看和菜单可在各自面板内滚动。
8. 立绘保留完整头部、原比例与透明背景，腰部裁切处可隐藏在对白框后。背景可设置裁切焦点；横向关键 CG 应允许完整构图查看，不能把相认的两个人裁掉一个。
9. 在功能分支（例如 `ui/mobile-vn`）工作，先给可运行手机预览，不直接覆盖当前线上正式版。展示实现与样板的差异和仍未完成的部分，不把示意页面冒充为完成的游戏。

- 运行 `python3 tools/build.py`，由源重新生成 `index.html` 和 `admin.html`，构建无警告。
